**Mode:** in the build flow, follow the `one-shot` steps wherever this
skill or its references give per-mode steps — decide and proceed; don't stop
to confirm with the user.

The project is your workdir: Studio runs inside one Reactor Package project
and creates no other one (`ph init` makes a new project, outside Studio).
Its run — `ph run vetra dev`, the project's own Switchboard, Connect and
preview drive on its own ports — is opt-in: `reactor-project-start` is in
your tools only when the Studio turns the project run on.

## Phase 0 — Bootstrap

    reactor-project-ps
    reactor-project-start { }     # only when it is in your tools; idempotent; warms the BUILD pane

**Gate:** `reactor-project-ps` lists the project as running. With the run
off there is nothing to start: build through the `spec-*` tools and the
checks, and say the preview comes with the Preview run.

## Before starting

- **Always run `reactor-project-ps` first.** If the project is running, do
  nothing; if it is stopped, `reactor-project-start` it.
- Never hand-write a project's files, and never make a second project in
  the workdir.

## Restart discipline

Do **not** call `reactor-project-restart` after spec changes, generated
code updates, or component-source edits. The spec watcher + Vite HMR
pick those up automatically. The one legitimate trigger for a restart:
`reactor-project-logs` shows the watcher *missed* an edit (no rebuild
log line after the change landed). Restarting otherwise wastes the
user's time and resets in-memory state.

## Endpoints

`reactor-project-start` output is the source of truth for the project's
ports and URLs (`mcp-server`, `vetra-studio`, `vetra-drive-url`,
`vetra-preview-drive-url`, `vetra-switchboard`). Re-read it rather than
assuming default ports.
